# 会话读取协议

只在需要扫描本机历史时打开对应小节。用户直接粘贴或导出对话时，不读本文件里的路径，从粘贴正文里区分用户自己的话、粘贴的助手回答和粘贴的文档。

不承诺能够遍历全量。路径或字段对不上、权限不足、或工具被拒绝时，报告已读范围和缺口，改走退路。退路是：请用户粘贴相关原话，或提供他自己导出的记录。不要把没读到的系统说成已经看过。

## 所有来源都要做的区分

用户自己的话才能当证据。算作用户自己的话：他亲手写的问题、纠正、决定。

不算作用户自己的话：

- 助手回复，即使用户把它粘进了自己的消息
- 用户粘贴的旧文档、任务书、审查报告
- 子代理的内部记录
- 系统通知和工具回执

纯派工，例如「按这个提交去实现」，不能当成未问出口问题的证据。它要单独留下来，用来判断用户是否已经作出决定。丢掉它，可能把「已问出口」误判成「新发现」。

同一会话出现在多个目录时只计一次。空会话不计。文件数和用户直接会话数分开报告。

## Cursor

下面是已经核对过的读取方式。格式以后变了，就停止沿用，改走退路。

- 对话搜索：一次一到两个关键词，多查几次。它返回标题和片段，不是全文。
- 本地转录：用户目录下 `.cursor/projects/<项目>/agent-transcripts/<会话>/<会话>.jsonl`。同一会话可能在 `empty-window` 和项目目录各有一份。
- 索引里的空会话：气泡数为 0 的条目跳过。
- 应用数据库里的会话索引可能存在，但读取可能被拒绝。被拒绝就记入读不到的部分，不改用别的办法硬读。

## Codex

下面是已经核对过的读取方式。格式以后变了，就停止沿用，改走退路。

- 索引：用户目录下 `.codex/session_index.jsonl`，字段有 `id`、`thread_name`、`updated_at`。索引不是全文。
- 会话文件：`.codex/sessions/年/月/日/rollout-*.jsonl`。用户自己的话在 `role` 为 `user` 的记录里。`developer` 和 `assistant` 不是用户原话。
- 归档目录 `.codex/archived_sessions` 只在主目录缺记录时再看。两边都有的同一 `id` 只计一次。

## 报告句

读完用两句话说明：文件大约多少、其中用户直接会话多少、时间跨度、哪一类被排除、哪一个来源没读到。做不到的那一部分直接写「读不到」。
